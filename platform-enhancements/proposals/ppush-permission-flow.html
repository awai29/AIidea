不在用戶第一次進站就要求授權，而是等到意圖最強的時刻再出現 — 先顯示我們自製的預授權 Sheet，再觸發 Chrome 原生授權對話框。 特別設計的隱私模式，讓用戶選擇要不要在通知欄中顯示平台相關資訊。

Section 01

觸發時機

什麼時候問，跟怎麼問一樣重要。在用戶正向情緒最高、推播最有意義的時機出現。

P1
首次存款後
最優先
資金剛入帳 — 正向情緒最高點。
推播重點：存款加碼、優惠額度通知。
P2
首次下注後
高優先
已下注，在場上有利益 — 想知道結果。
推播重點：賽果通知、賠率變動。
P3
第 3 次登入、仍未訂閱
中優先
確認是回流用戶 — 有繼續使用的意願。
推播重點：優惠到期提醒、個人化推薦。
P4
瀏覽優惠頁 30 秒以上
情境觸發
對優惠有興趣 — 推播高度相關。
推播重點：優惠截止倒數、新活動上線通知。
P2
連續登入 3 天
習慣養成
持續回來 — 習慣已建立。包裝成「解鎖獎勵」而非「請求授權」。
P2
首次申請出金後
信任已建立
用戶完成了完整的金流週期 — 信任度最高。「到帳通知你」直接解決他的焦慮。
P2
首次贏錢後
情緒高峰
贏錢是最強的正向情緒時刻。「下次想第一個知道嗎？」— 轉換率非常高。
✕
第一次進站就問
授權率極低（<5%） — 用戶還不認識平台，信任度為零。
✕
用戶未登入
無用戶資料 — 推播無法個人化，也不符合合規要求。

再觸發邏輯

「稍後」不代表永不。在適當間隔重新邀請；對已封鎖的用戶絕不再打擾。

點了「稍後」
1
記錄狀態 + 等待 7 天
localStorage 儲存 dismissedAt — 7 天內不再重新提示
2
第 2 次觸發（7 天後）
在下一個 P1/P2 時機（存款或下注）再次顯示預授權彈窗
3
第 3 次觸發（再 14 天後）
最後一次主動詢問 — 之後不再打擾
✓
設定頁面永遠開放
帳號設定 → 通知 — 隨時可自行開啟
點了「封鎖」（Chrome 原生）
!
無法再次觸發原生對話框
Chrome 封鎖後，任何 Permission API 呼叫都會被靜默忽略
→
在設定頁顯示手動解鎖指引
帳號設定 → 通知偏好設定 → 逐步解鎖說明
→
Chrome 手動解鎖步驟

Section 06

技術實作 — Payload 對比

後端根據用戶的 notificationMode 建構不同的 Payload。兩種模式都包含 DeepLink。

● 標準模式
// notificationMode === 'normal'
{
  "title":   "⚽ BAN vs QAT Pre-match Alert",
  "body":    "Home win 1.85 · Bet Now",
  "icon":    "/icons/bj-logo-192.png",
  "badge":   "/icons/badge-mono-96.png",
  "image":   "/images/ban-qat-banner.jpg",
  "actions": [
    { "action": "bet",  "title": "Bet Now" },
    { "action": "view", "title": "View Odds" }
  ],
  "data": { "deepLink": "/match/ban-qat" }
}
● 隱私模式
// notificationMode === 'privacy'
{
  "title":  "You have a new message",
  "body":   "Tap to view details",
  "icon":   "/icons/generic-bell-192.png",

  // badge / image / actions all omitted

  "data": { "deepLink": "/match/ban-qat" }
  // deepLink still included — tap opens normally
}
後端邏輯：發送前先查用戶的 notificationMode（儲存於用戶資料庫）。標準模式 → 完整 Payload；隱私模式 → 最小化 Payload。
無法隱藏：Android Chrome 通知永遠會在來源列顯示「Chrome · bj.com」— 這是 Chrome 規格強制要求，無法透過 Payload 控制。
