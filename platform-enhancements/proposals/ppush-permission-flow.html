Section 01

觸發時機

什麼時候問用戶，和接受率直接相關。在正向情緒高、推播最相關的時刻出現。

P1
首次存款成功後
最高優先

推播 benefit 聚焦：存款獎勵、優惠到帳通知。
P2
首次投注成功後
高優先
有皮膚在局裡，最想知道比賽結果。
推播 benefit 聚焦：比賽結果、賠率變動。
P3
第 3 次登入，仍未訂閱
中優先
確認是回頭客，有使用意願。
推播 benefit 聚焦：優惠到期、個人化推薦。
P4
主動瀏覽優惠頁 30 秒以上
情境觸發
對優惠有興趣，推播最相關。
推播 benefit 聚焦：優惠截止、新優惠上架。
✕
一進網站就問
接受率極低（<5%），用戶完全不認識平台，沒有信任基礎。
✕
未登入狀態
沒有用戶資料，推播無法個人化，且不符規範要求。

Section 05

再觸發邏輯

用戶說「稍後」不代表永遠不要，節制地再問；用戶選「封鎖」則不再主動打擾。

點「稍後再說」
1
記錄狀態 + 等 7 天
localStorage 存 dismissedAt，7 天內不再彈出
2
第 2 次觸發（7 天後）
下一個 P1/P2 時機（存款或投注後）再出現說明 Sheet
3
第 3 次觸發（再 14 天後）
最後一次主動詢問，之後不再打擾
✓
設定頁永遠可手動開啟
帳號設定 → 通知偏好，隨時可以開啟

!
無法再呼叫原生彈窗
Chrome 封鎖後，我們呼叫 permission API 會被靜默忽略

Section 06

技術實作 — Payload 對比

後端根據用戶的 notificationMode 組不同 Payload 送出。DeepLink 兩者都送。

● 一般模式
// notificationMode === 'normal'
{
  "title":   "⚽ BAN vs QAT 賽前推播",
  "body":    "主隊勝 1.85 · 立即投注",
  "icon":    "/icons/bj-logo-192.png",
  "badge":   "/icons/badge-mono-96.png",
  "image":   "/images/ban-qat-banner.jpg",
  "actions": [
    { "action": "bet",  "title": "立即投注" },
    { "action": "view", "title": "查看賠率" }
  ],
  "data": { "deepLink": "/match/ban-qat" }
}
● 隱私模式
// notificationMode === 'privacy'
{
  "title":  "您有一則新訊息",
  "body":   "點擊查看詳情",
  "icon":   "/icons/generic-bell-192.png",

  // badge / image / actions 全部不送

  "data": { "deepLink": "/match/ban-qat" }
  // deepLink 仍送，點開後正常導向
}
後端邏輯：送推播前查用戶的 notificationMode（存於 user profile DB）。Normal → 完整 payload；Privacy → 精簡 payload。
無法隱藏的：Android Chrome 通知卡片的來源列固定顯示「Chrome · bj.com」，這是 Chrome 規範強制呈現，非 payload 控制範圍。
