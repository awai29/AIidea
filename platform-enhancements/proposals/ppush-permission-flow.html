Push Permission + Privacy Mode

Rather than asking on first visit, we wait for the highest-intent moment — showing our own custom pre-prompt Sheet first, then triggering the native Chrome permission dialog. A special Privacy Mode lets users choose whether to show platform or betting-related content in the notification shade.

Section 06

Technical Implementation — Payload Comparison

The backend builds different payloads based on the user's notificationMode. DeepLink is included in both.

● Normal Mode
// notificationMode === 'normal'
{
  "title":   "⚽ BAN vs QAT Pre-match Alert",
  "body":    "Home win 1.85 · Bet Now",
  "icon":    "/icons/bj-logo-192.png",
  "badge":   "/icons/badge-mono-96.png",
  "image":   "/images/ban-qat-banner.jpg",
  "actions": [
    { "action": "bet",  "title": "Bet Now" },
    { "action": "view", "title": "View Odds" }
  ],
  "data": { "deepLink": "/match/ban-qat" }
}
● Privacy Mode
// notificationMode === 'privacy'
{
  "title":  "You have a new message",
  "body":   "Tap to view details",
  "icon":   "/icons/generic-bell-192.png",

  // badge / image / actions all omitted

  "data": { "deepLink": "/match/ban-qat" }
  // deepLink still included — tap opens normally
}
Backend logic: check user's notificationMode (stored in user profile DB) before sending. Normal → full payload; Privacy → minimal payload.
Cannot hide: Android Chrome notification always shows "Chrome · bj.com" in the source row — this is enforced by Chrome spec, not controllable via payload.

Android Chrome Web Push

Why target this user

He just lost a streak, morale is low, churn risk is high — but the backend confirms he qualifies for Loss Rebate
→ "Platform steps in with a reward — he feels cared for, not exploited"

Key: don't push on every loss — only push when "loss streak + eligible to claim." Otherwise it's spam.
