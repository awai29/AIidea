Angular 實作方向 — BO 繼續上傳 3x，前端自動依 DPR 選圖
✅ BO 上傳流程不需要改，繼續上傳原始 3x 圖。前端或 CDN 自動產生 1x / 2x 縮圖，裝置只下載需要的尺寸。
方式一 — srcset 屬性（純 HTML）
零 JS需 CDN resize
<!-- 搭配 Cloudflare Image Resizing --> <img srcset=" /cdn-cgi/image/w=116/game.png 1x, /cdn-cgi/image/w=232/game.png 2x, /cdn-cgi/image/w=348/game.png 3x " src="/cdn-cgi/image/w=232/game.png" loading="lazy" alt="game cover" />
瀏覽器依 DPR 自動選：1x → 116px / 2x → 232px / 3x → 348px（原圖）。
推薦
方式二 — Angular CdnService
全站生效只改 ServiceCloudflare
// cdn.service.ts @Injectable({ providedIn: 'root' }) export class CdnService { private readonly DPR_MAP: Record<string,number> = { '1x': 116, '2x': 232, '3x': 9999, }; getImageUrl(src: string): string { const dpr = window.devicePixelRatio ?? 1; const tier = dpr >= 2.5 ? '3x' : dpr >= 1.5 ? '2x' : '1x'; const w = this.DPR_MAP[tier]; // Cloudflare: /cdn-cgi/image/w={w}/original-path return w === 9999 ? src : src.replace('/images/', `/cdn-cgi/image/w=${w}/images/`); } }
只改 CdnService，全站圖片自動受益。不需逐一修改元件。
方式三 — Angular ImagePipe
Template 乾淨搭配方式二
// image.pipe.ts @Pipe({ name: 'cdnImg', standalone: true }) export class CdnImagePipe implements PipeTransform { constructor(private cdn: CdnService) {} transform(src: string) { return this.cdn.getImageUrl(src); } } // 元件 template 用法 <img [src]="game.thumbnail | cdnImg" loading="lazy" [alt]="game.name" />
Pipe 包一層，template 不需要直接呼叫 service，便於測試與替換。
DPR 對應規則
東南亞裝置參考
devicePixelRatio 裝置類型 寬度 ─────────────────────────────────────────────── < 1.5 桌機 / 舊裝置 → 1x (116px) 1.5 – 2.4 iPhone XR/11 / 舊 Android → 2x (232px) ≥ 2.5 Samsung Galaxy / iPhone 14+ / Pixel 6+ （主流 ~90%） → 3x (348px)

批次轉換 1000 張 PNG 的方法比較
⚠️ JPG 為有損格式，PNG→JPG 技術上一定有損失。真正無損只有 WebP lossless（quality=100 + lossless:true）。若接受視覺無損（quality ≥ 95），轉 JPG 可行。PNG 支援透明背景，JPG 不支援——有透明度的圖轉 JPG 會填白底。
最佳解
Sharp (Node.js)
ScriptMac/Win/Linux最快 4–8×
npm install sharp node -e " const sharp=require('sharp'),fs=require('fs'); fs.readdirSync('./png') .filter(f=>f.endsWith('.png')) .forEach(f=>sharp('./png/'+f) .jpeg({quality:95,mozjpeg:true}) .toFile('./jpg/'+f.replace('.png','.jpg'))); "
libvips 底層，比 ImageMagick 快 4–8×。mozjpeg:true 同品質再小 10–15%。
WebP lossless: .webp({lossless:true})
ImageMagick mogrify
CLIMac/Win/Linux最廣泛
brew install imagemagick mkdir jpg mogrify -format jpg -quality 95 \ -path ./jpg ./png/*.png
一行指令，1000 張約 30–90 秒。WebP lossless: 加 -define webp:lossless=true -format webp
Squoosh CLI (Google)
CLI同時輸出 JPG+WebP
npm i -g @squoosh/cli squoosh-cli \ --mozjpeg '{"quality":95}' \ --webp '{"quality":85}' \ --output-dir ./out ./png/*.png
一次輸出 JPG 和 WebP 兩個版本，方便搭配 <picture> fallback。
WebP 破圖的正確解法
HTML only零 JS
<picture> <source srcset="photo.webp" type="image/webp"> <img src="photo.jpg" alt="..."> </picture>
支援 WebP → 用 WebP；不支援 → 自動 fallback JPG。完全零風險，不需 JS 偵測。Safari 14 以前完整覆蓋。

三種網路偵測方式比較
💻
前端偵測
navigator.connection
優點
  • 免費，零後端成本
  • 即時偵測，無需 round-trip
  • 可監聽 change 事件動態切換
  • 靜態網站也能用（本 Demo 即此方式）
缺點
  • 僅 Chrome / Android 支援，Safari / Firefox 不支援
  • effectiveType 是估算值，非真實頻寬
  • VPN / 代理可能造成誤判
適合場景
靜態網站、原型、APP WebView
推薦度：中
🖥
後端偵測
HTTP Client Hints
做法
  • Server 回 Accept-CH: ECT, Downlink, Save-Data
  • 瀏覽器後續請求自動帶 hint headers
  • Server 依 header 回傳對應尺寸
優點
  • 無需前端 JS，可搭配 SSR 首屏直出正確尺寸
  • Save-Data 明確表達使用者節流意願
缺點
  • 第一次請求不帶 hint（需 Critical-CH）
  • 底層仍依賴 navigator.connection 數據
  • 需後端邏輯，增加維護複雜度
適合場景
有 SSR 的 Web App（Next.js / Nuxt）
推薦度：中
🌐
CDN 邊緣偵測
Cloudflare Image Resizing
優點
  • 原始只需一張高解析度圖，無需預生成多版本
  • format=auto 自動 WebP fallback，完全解決破圖
  • 全球 CDN 邊緣加速，延遲最低
  • Polish 功能自動進一步壓縮
缺點
  • Image Resizing 需 Pro 方案（$20/月起）
  • 綁定 Cloudflare 供應商
  • 網路速度仍需前端或 Client Hints 配合
適合場景
生產環境、大流量、需自動 WebP fallback
推薦度：高（生產首選）
Cloudflare Image Resizing — 前端整合（結合 navigator.connection）
const CF = 'https://example.com/cdn-cgi/image'; const cfg = { 'slow-2g': 'width=100,quality=40,format=auto', '2g': 'width=100,quality=50,format=auto', '3g': 'width=400,quality=70,format=auto', '4g': 'width=1200,quality=85,format=auto', }; const type = navigator.connection?.effectiveType ?? '4g'; img.src = `${CF}/${cfg[type]}/images/hero.jpg`; // format=auto: 支援 WebP → 給 .webp；不支援 → 自動給 .jpg
