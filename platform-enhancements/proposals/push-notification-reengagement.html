04
頻率控制 & 冷卻機制
過度推播是流失的直接原因之一。需設置全局上限、情境冷卻、轉換後靜默三層保護。
🔒 全局頻率上限
  • 每位用戶每日最多 2 則推播（不含即時觸發類）
  • 每週最多 8 則，超過自動排隊至下週
  • 用戶連續 3 次未開啟 → 自動降級至每週 2 則
  • 用戶手動關閉任一則 → 同類情境冷卻 72h

⏱ 情境冷卻時間
  • D+1 輕度喚醒：觸發後冷卻 24h，下次跳至 D+3
  • D+3 偏好召回：觸發後冷卻 48h
  • D+7 高價值：觸發後冷卻 72h，優惠不重疊
  • 存款未投注：2h → 6h → 24h 三梯次，投注即停止
  • 用戶登入後：所有回流類推播靜默 48h
  • 用戶完成投注：所有召回類靜默 72h
🛡 過度推播保護（Fatigue Guard）
Level 1 — 警告
7天內推播 > 10則
→ 系統標記，下週限制發送頻率
Level 2 — 降頻
連續 5 則未開啟
→ 自動切換為每週 1–2 則低頻模式
Level 3 — 停播
用戶主動取消訂閱
→ 停止所有推播，僅保留交易通知

⚠️ 每次只測試一個變數。同時改文案 + 時間 + 優惠會讓你無法判斷哪個因素有效。

技術架構 — FCM Payload 與站臺 Logo 控制痛點
目前以 FCM payload 控制各平台通知 icon，Web 端與 Android 端的實作機制根本不同，存在無法用同一套邏輯解決的結構性差異。
FCM Payload 結構（現行做法）
Web Push
{ "message": { "topic": "reengagement", "webpush": { "notification": { "title": "回來試試手氣 🎰", "body": "{name}，你的專屬優惠等你", "icon": "https://cdn.example.com/logo-site-a.png", // ✅ 接受 URL，直接顯示站臺 logo // ⚠️ 需 HTTPS + CORS // ⚠️ 建議尺寸 192×192 px "badge": "https://cdn.example.com/badge.png" } } } }
Android（FCM）
{ "message": { "topic": "reengagement", "android": { "notification": { "title": "回來試試手氣 🎰", "body": "{name}，你的專屬優惠等你", "icon": "ic_stat_site_a", // ❌ 只接受 drawable resource name // ❌ 無法傳 URL，傳了會被忽略 // ❌ 必須預先編譯進 APK "color": "#FF6B00" } } } }
技術痛點分析
❌ Android icon 不支援 URL
最核心的結構問題
android.notification.icon 欄位只接受 APK 內已編譯的 drawable resource name（如 ic_stat_logo），無法傳入 URL。傳 URL 字串不會報錯，但 FCM 找不到對應 resource 時直接改用 App 預設 icon，站臺 logo 完全無法顯示。
❌ Android icon 必須是單色
Android 5.0+ 系統強制規定
Android 5.0（API 21）起，通知欄 small icon 只允許白色透明背景（monochrome alpha-only）。若 drawable 有彩色，系統會自動渲染成純色剪影，站臺 logo 顏色全部消失，只剩輪廓。彩色 logo 直接用會顯示錯誤。
⚠️ 白牌多站臺 APK 問題
每個站臺需獨立打包
若平台有多個白牌站臺（site-a、site-b…），每個站臺的 Android APK 都需要各自編譯對應的 ic_stat_sitename drawable。無法透過 FCM payload 動態切換，站臺新增或 logo 更版都需要重新打包 + 上架 Google Play。
⚠️ Web icon URL 快取問題
Logo 更新後用戶看到舊圖
Chrome 會積極快取通知 icon URL。若站臺更換 logo 但沿用相同 URL，已訂閱用戶可能數天內仍看到舊 logo。需使用版本化 URL（如 logo-v2.png 或帶 hash 的 CDN 路徑）並同步更新推播模板。
⚠️ iOS 無法換 small icon
但可用 NSE 顯示 logo 縮圖
APNs payload 沒有 icon 欄位，狀態列小 icon 永遠是 App icon 無法動態替換。但可透過 Notification Service Extension（NSE） 攔截推播，將 logo 以附件縮圖形式呈現在 banner 右側，視覺效果比 small icon 更顯眼。
✅ Web Push 相對可行
唯一支援 URL 的平台
Web Push 的 webpush.notification.icon 完整支援 HTTPS URL，可直接帶入各站臺 logo CDN 路徑，不需改動 App。需確保：① CDN 回應 CORS header、② icon 為正方形 192px+、③ URL 使用版本化命名。
iOS 解法 — Notification Service Extension（NSE）
NSE 是 iOS 原生機制，可在通知送達用戶裝置後、顯示前攔截並修改內容。只需在 APNs payload 加 "mutable-content": 1，App 端的 NSE target 就會被喚醒，可下載 logo URL 並以 UNNotificationAttachment 附加到通知，出現在 banner 右側縮圖及展開後的大圖位置。
後端：APNs payload（透過 FCM apns block）
{ "message": { "token": "apns_device_token", "apns": { "payload": { "aps": { "alert": { "title": "回來試試手氣 🎰", "body": "你的專屬優惠等你" }, "mutable-content": 1, // ← 必填，啟用 NSE "sound": "default" }, // 自訂欄位，NSE 可讀取 "logo_url": "https://cdn.example.com/logo-site-a.png", "deep_link": "app://promo/reengagement" } } } }
iOS App：NotificationService.swift（NSE target）
// Swift — Notification Service Extension class NotificationService: UNNotificationServiceExtension { override func didReceive( _ request: UNNotificationRequest, withContentHandler handler: @escaping (UNNotificationContent) -> Void ) { let content = request.content.mutableCopy() as! UNMutableNotificationContent guard let urlStr = request.content.userInfo["logo_url"] as? String, let url = URL(string: urlStr) else { handler(content); return } // 下載 logo 並建立附件 URLSession.shared.downloadTask(with: url) { tmp, _, _ in if let tmp, let att = try? UNNotificationAttachment( identifier: "logo", url: tmp, options: [UNNotificationAttachmentOptionsTypeHintKey: "public.png"] ) { content.attachments = [att] // ← 顯示在 banner 右側縮圖 } handler(content) }.resume() } // NSE 超時 fallback（iOS 強制 ~30s 限制） override func serviceExtensionTimeWillExpire() { handler?(bestAttemptContent ?? request.content) } }
✅ NSE 的優點
• 不需重新打包 App，新站臺只要改 logo_url
• 彩色 logo 完整顯示，無單色限制
• 展開通知後 logo 放大，品牌感更強
• iOS 10+ 全版本支援
⚠️ NSE 的限制
• Small icon（狀態列左上角）仍固定為 App icon，無法改
• NSE 執行時間上限約 30 秒，超時 fallback 無附件
• 需在 Xcode 額外建立 NSE target 並上架新版本（一次性）
• App 在背景被系統殺掉時 NSE 可能無法執行
Android 動態 Logo 的繞過方案
FCM 原生 notification 訊息無法做到 Android 動態 icon。需改用 Data Message + 自訂 FirebaseMessagingService，在 App 端攔截並自行建構通知。
後端：改發 Data Message（不帶 notification block）
{ "message": { "token": "device_fcm_token", "data": { "title": "回來試試手氣 🎰", "body": "你的專屬優惠等你", "logo_url": "https://cdn.example.com/logo-site-a.png", "deep_link": "app://promo/reengagement" } // ✅ 不加 "android.notification" block // → FCM 不自動顯示通知 // → App 端的 onMessageReceived() 才會被呼叫 } }
Android App：FirebaseMessagingService 自訂通知
// Kotlin class PushService : FirebaseMessagingService() { override fun onMessageReceived(msg: RemoteMessage) { val data = msg.data val logoUrl = data["logo_url"] ?: return val title = data["title"] ?: "" val body = data["body"] ?: "" // 用 Glide 下載 logo（需先 cache） val bitmap = Glide.with(this) .asBitmap().load(logoUrl) .submit(192, 192).get() val notif = NotificationCompat.Builder(this, CHANNEL_ID) .setSmallIcon(R.drawable.ic_stat_default) // monochrome fallback .setLargeIcon(bitmap) // ← 彩色 logo 放這裡 .setContentTitle(title) .setContentText(body) .build() NotificationManagerCompat.from(this) .notify(NOTIF_ID, notif) } }
重點：彩色站臺 logo 放 setLargeIcon()（右側大圖），setSmallIcon() 繼續用 APK 內的單色 drawable。這樣 Android 5.0+ 顯示正確，又能動態顯示站臺品牌色彩，不需重新打包 APK。
