01
技術架構 — 網頁推播不需要完整 PWA
釐清 PWA vs Web Push 的關係，以及現有 Firebase FCM 架構的定位
✅
不需要完整 PWA，但需要 Service Worker
推播通知的技術依賴是 Service Worker + HTTPS + 用戶授權，跟「是否為 PWA」無關。
你們已在用 Firebase FCM，FCM SDK 會自動注冊一個 Service Worker（firebase-messaging-sw.js）。
App Manifest、離線功能、可安裝性 — 這些 PWA 特性對推播 沒有影響，不需要實作。
✅ 推播必要條件（你們已有）
✓
HTTPS — 所有推播 API 只在 HTTPS 下運作
✓
Service Worker — Firebase SDK 自動注冊 firebase-messaging-sw.js
✓
Firebase FCM — Server-side 推送訊息的基礎設施
✓
用戶授權 — Notification.requestPermission() 彈窗
✓
FCM Token — 每裝置唯一識別符，存在後端 DB
❌ 推播不需要的 PWA 特性
✗
Web App Manifest（manifest.json）— 只影響安裝行為
✗
離線快取（Cache API）— 與推播無關
✗
可安裝性（A2HS / Install Prompt）— 非必要
✗
App Shell 架構 — PWA 設計模式，不影響推播
✗
背景同步（Background Sync）— 不同 API
⚠️ iOS 例外情況：
Safari 16.4（2023/3）才支援 Web Push，且有一個關鍵限制：用戶必須先「加入主畫面」（A2HS）才能授權推播。
這意味著 iOS Safari 上的推播觸及率會遠低於 Android。

若用戶群中 iOS 比例高，建議評估：① 引導 A2HS 流程 ② 開發 iOS App（FCM + APNs，完整支援 Rich Notification）
目前 Android 用戶（FCM WebPush）可立即享受完整 image + action button，不受限制。

①② 顯示「Chrome」+ Chrome icon — OS 固定顯示 Browser 名，icon 也是 Chrome 預設，玩家認不出品牌
③ 右上角「F」頭像 — 瀏覽器帳號圖，前端無法干預

⑤ 同類通知重複疊加 — 無 tag，每筆存款都推一則，塞滿通知欄
⑥ 純文字，無圖 / 無品牌感 — 和其他 App 通知無任何視覺區別
❌ 無圖片
無 image / icon，通知顯示為純文字，無視覺辨識度
❌ 無 Action
無 actions 陣列，玩家只能點開通知無法直跳目標頁
❌ 無 Deep Link
data 僅有 notificationType:1，點擊後無法導向對應功能頁
⚠ 訊息固定化
文案千篇一律，無玩家分群邏輯，ABCD 人格全拿到同一則通知
🛠 前端（Service Worker）可以直接做的事
FCM 把 payload 送到 SW 的 push 事件後，由 SW 決定要顯示什麼樣的通知 — 這層完全在前端控制，不需要後端額外配合就能改善四個問題
✅ 前端可以改（SW showNotification 選項）
icon
品牌 Logo URL → 取代 Chrome 預設圖，玩家一眼認出平台
badge
小型單色 icon，顯示於 Android 狀態列 / 鎖定畫面角標
image
通知展開後顯示大圖（Android Chrome）；存款成功可放金幣圖或品牌 banner
tag
相同 tag 的通知只顯示一則 → 解決「重複疊加」問題，如 "deposit-approved"
actions[]
新增 CTA 按鈕，如「Deposit Now」「Play Now」；點擊觸發 notificationclick 事件
requireInteraction
通知不自動消失，玩家必須手動關閉或點擊，提高曝光時間
vibrate
自訂震動模式，如 [200,100,200]，讓存款通知有不同觸感
❌ 前端改不了（OS / Browser 控制）
「Chrome」文字 → OS 顯示 Browser 名稱，不可自訂
域名「feuatcb.bkw168...」→ 顯示推播來源域，不可修改
右上角「F」頭像 → 瀏覽器登入帳號圖片，前端無法干預
iOS Safari：actions 按鈕不支援，需降級為純 body 文案
firebase-messaging-sw.js — 改這裡就夠了
messaging.onBackgroundMessage((payload) => {
