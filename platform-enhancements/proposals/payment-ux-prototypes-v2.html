原型 1 · Step 2 最大流失點
方式選擇頁改善

數據顯示最大流失在 Step 2（In Types 畫面）。玩家進入存款後，看到四個選項卻沒有任何引導，大量在這裡離開。這組原型展示現況問題和改善方向。

狀態 1 — 現況問題（In Types 選擇頁）
玩家進入存款後，看到四個方式選項，沒有任何引導或說明。這是整個流程最大的流失點。
數據事實
  • !Step 1 → Step 2 漏斗：237,059 人進入存款 → 只有 63,244 人選擇方式（僅 26.7%）
  • !這意味著 73% 的玩家在看到方式選擇頁後就離開了
  • !In Types 頁面有四個選項，但沒有任何說明、推薦或個人化提示
問題根源
  • →玩家不知道 Quick In / Local Bank / E-wallet / Crypto 各有什麼差別
  • →沒有任何個人化提示（例如：你上次用的是 E-wallet）
  • →選錯方式的懲罰高（要重新回來選）→ 玩家寧可不選
結論：In Types 頁面是最需要優先改善的地方。增加說明和個人化預選，預估可提升此步驟的通過率。
狀態 2 — 改善：預選上次使用方式
根據玩家歷史，自動高亮「上次使用」的方式，讓玩家一眼就知道選什麼，不必重新思考。
改善設計重點
  • ✓高亮玩家上次成功存款使用的方式（綠色邊框 + 「上次使用」標籤）
  • ✓每個方式加一行簡短說明（速度、常見用途）
  • ✓底部按鈕改為「繼續用 E-wallet」，讓玩家不需再想
技術需求
  • →讀取玩家最近一次成功的 deposit_method 欄位
  • →如果玩家沒有歷史（首次），顯示「新手推薦」邏輯（見狀態 4）
設計邏輯：預設上次選擇可讓玩家不需要重新思考，直接確認即可。常規路徑零阻力是存款流程最重要的設計原則。
狀態 3 — 維護中明確標示
某個方式維護時，目前可能讓玩家點進去才發現失敗。應在列表就告知，並引導到可用選項。
改善設計重點
  • ✓維護中的方式保留顯示，但加上「維護中」標籤和半透明效果，不讓玩家點擊
  • ✓顯示預計恢復時間（如果系統能提供）
  • ✓自動高亮下一個推薦的可用方式（「推薦替代」標籤）
技術需求確認
  • !系統能否即時知道哪個通道維護中？需向後端確認 API 是否有這個狀態欄位
  • !預計恢復時間是否能從系統取得，或只能說「暫時不可用」
設計原則：讓玩家在選擇前就知道哪個不可用，比讓他選了才失敗好得多。顯式禁用優於靜默移除或事後報錯。
狀態 4 — 首次存款引導（FTD）
第一次存款的玩家完全不知道各方式有什麼差別，需要更多引導，否則直接離開。
改善設計重點
  • ✓頁面頂部加一行提示：「建議新玩家從 E-wallet 開始，最快最方便」
  • ✓每個方式下方加簡短說明（到帳速度、適合對象）
  • ✓「新手推薦」方式加上醒目標籤，底部按鈕引導直接選擇
技術需求
  • →判斷 FTD 條件（玩家沒有任何成功存款紀錄）
  • →此邏輯只顯示一次，之後切換為「預選上次方式」模式
FTD 轉換率直接影響長期留存。首次存款體驗越順暢，7 日留存率越高。這是優先度最高的 FTD 改善措施之一。

原型 2 · Step 3 最大流失點（第二）
表單精簡改善

數據顯示 Step 3（表單頁）是第二大流失點。目前玩家進入表單後要做 4 層決策（方式 → 類型 → 通道 → 優惠）才能填金額。這組原型展示如何大幅減少摩擦。

狀態 1 — 現況問題（E-wallet 表單頁）
玩家選完方式後進入表單，要做 4 層決策才能填金額。每一層都可能是放棄點。
4 層決策流程（按順序）
  • !第 1 層：優惠選擇 — 頁面頂部的 Promotion 橫幅，要求先選優惠才能繼續
  • !第 2 層：付款方式選擇 — 7 個選項（bKash / Nagad / Rocket / OK Wallet / Upay / SureCash...）
  • !第 3 層：Type 下拉選單
  • !第 4 層：Channel 下拉選單
問題分析
  • →玩家在還沒填金額前，就要做 4 個決定 — 認知負荷過高
  • →優惠選擇放在最前面，但玩家不知道存多少才能用，只好跳過或放棄
  • →Type 和 Channel 的差別對大多數玩家不直覺
數據：Step 3 流失率高（62,958 人完成表單 vs 63,244 人進入）。雖然表面上看通過率高，但這是因為「沒填完就離開的人」已在 Step 2 流失，到這裡的都是意願最強的玩家。
狀態 2 — 精簡：自動帶入上次設定
回頭玩家已有存款紀錄，系統自動帶入上次成功的所有設定，玩家只需要填金額。
改善設計重點
  • ✓進入表單時，自動帶入上次的方式（bKash）、Type、Channel
  • ✓用一個緊湊的摘要列顯示所有預填設定，右側「更換」可一鍵切換
  • ✓金額輸入框放在最顯眼的位置，讓玩家第一眼就知道要做什麼
  • ✓快速金額選項（chips）排在金額框下方，不需要捲動
技術需求
  • →讀取玩家上次成功存款的 type / channel / amount 設定
  • →如果上次的通道已停用，自動選下一個可用的同類通道
儲存方案：後端 User Profile
  • ✓儲存位置：users 資料表新增 3 個欄位
  • ✓last_deposit_type — 存款類型，如 "e_wallet"、"local_bank"、"crypto"
  • ✓last_deposit_channel — 管道，如 "bkash"、"nagad"、"usdt"
  • ✓last_deposit_amount — 金額整數，如 500
  • →寫入時機：存款成功 callback 後更新這 3 個欄位
  • →讀取時機：進入存款頁時，API 回傳 user profile 帶入畫面
目標：把「填金額 → 送出」縮短成 2 步，而非現在的 6 步（選優惠 + 選方式 + 選 Type + 選 Channel + 填金額 + 送出）。
狀態 3 — 切換方式體驗
當玩家想換方式時，應從簡潔的摘要列直接展開選擇，不跳回到複雜的 7-tab 頁面。
改善設計重點
  • ✓點擊摘要列的「更換」→ 彈出底部 Sheet 顯示所有可用通道（格狀排列）
  • ✓每個通道卡片顯示名稱、Logo、是否有紅利標籤
  • ✓選完立刻關閉 Sheet，回到表單，摘要列同步更新
  • →設計原則：讓常規路徑（不換）零阻力，換方式也在 2 秒內完成
設計原則：格狀排列讓所有選項同時可見，不需要橫向滑動，減少漏看的可能性。
狀態 4 — 優惠自動套用
不讓玩家在填金額前選優惠。等玩家填完金額後，系統自動計算並顯示最適合的優惠。
改善設計重點
  • ✓移除表單頂部的 Promotion 選擇器
  • ✓玩家填完金額後，系統即時計算並顯示「已自動套用最優惠 · 點這裡查看詳情」
  • ✓如果有多個優惠，系統自動選最優惠的；玩家可以點「查看/更換」手動選
  • →數據支持：73% 的玩家在 Step 2 就離開，不是因為不要優惠，而是決策點太多
原則：主動幫玩家做好選擇，而非要求玩家主動理解所有選項。「你已獲得最佳優惠」比「請選擇優惠」轉換率更高。
狀態 5 — GA 優化：統一支付+優惠流程
根據 GA 行為數據與後端業務限制，重新設計支付方式與優惠的選擇邏輯。
GA 數據問題
  • !36.6% 放棄用戶陷入「換方式循環」，不斷切換支付方式卻只有 0.2% 完成 — 代表換方式的體驗讓人沮喪
  • !舊客在金額頁停留 31 分鐘（新客 12 分鐘），決策阻力在「不知道選哪個方式搭配什麼優惠」
  • !6.4% 用戶反覆查餘額循環 — 餘額焦慮，不確定「這個方式能不能用、能用多少」
後端業務限制 → 設計問題
  • !現況問題：玩家選完支付方式 → 再選優惠 → 發現優惠不支援此支付方式 → 被迫回頭改支付方式 → 流失
  • ✓業務數據：營運方確認大部分玩家都選預設優惠（default promotion）
  • ✓解法原則：「選支付方式」的同時就決定好優惠，兩個動作合一，不讓玩家發現不相容
State 5 設計改善
  • ✓顯示餘額 — 主表單上方顯示當前帳戶餘額，解決 6.4% 的「查餘額焦慮」循環
  • ✓優惠預設套用 — 進入時已自動套用 Default Promotion，顯示「AUTO」標籤，不需要玩家主動選
  • ✓統一 Sheet（Payment & Bonus） — 點「支付方式列」開啟一個 Sheet，選完支付方式後 下方即時更新 相容的優惠清單，在同一個 Sheet 內完成兩個決定
  • ✓智能預選 — 每次切換支付方式，系統自動選最佳相容優惠（通常就是 default），玩家只需確認即可
  • ✓上次金額記憶 — ৳1,000 ↩ chip 標示上次金額，回頭玩家一眼就知道慣用金額
  • ✓Toast 確認 — 確認後頁面顯示「已套用 100% 優惠」提示，讓玩家知道系統做了什麼
互動說明（點手機試試看）
  • →點「bKash 列」或「優惠列」→ 開啟 Payment & Bonus Sheet
  • →在 Sheet 中切換支付方式 → 下方相容優惠即時更新
  • →選 OKwallet 或 Crypto → 顯示「此方式無可用優惠」
  • →點「Confirm」→ 主頁面支付列+優惠列同步更新，出現 Toast 提示
核心原則：不讓玩家有機會犯「選了不相容組合」的錯誤。系統只展示可用選項，自動推薦最佳組合，玩家按 Confirm 就好。

原型 3
存款成功後 AI 引導

Direction A：通知只做「確認到帳」，推薦遊戲改用 Lobby 底部的持久 Banner。玩家關掉通知後，Banner 仍停留在畫面下方等待點擊，不錯過最佳引導時機。

狀態 1 — 有遊戲紀錄（Direction A）
頂部通知只確認到帳，底部 Banner 持續引導玩家繼續上次的遊戲。
  • ✓頂部 Toast：「Approved in · +৳1,000 has been approved.」— 純確認，不帶 CTA
  • ✓底部 Banner：「繼續上次 · Teen Patti [去玩]」— 通知消失後仍可見，不會錯過
  • →分離通知與推薦：通知只做確認（高可信度），Banner 做推薦（低壓力），功能清晰
畫面上同時顯示兩個元素，讓 reviewer 一眼看出「通知先出現 → 關掉後 Banner 還在」的流程邏輯。
狀態 2 — 首次存款 FTD（Direction A）
首存玩家無遊戲紀錄，通知確認到帳 + 發禮包，底部 Banner 引導試玩新手推薦遊戲。
  • ✓頂部 Toast：「Approved in · +৳500 has been approved. Welcome bonus sent.」
  • ✓底部 Banner：「新手推薦 · Color Prediction [試試]」— 低風險入門遊戲，降低首次遊戲門檻
  • !FTD 後首次遊戲體驗決定回頭率，Banner 是新玩家第一個遊戲行為的入口
狀態 3 — 解鎖優惠門檻（Direction A）
通知確認到帳 + 告知紅利解鎖，底部 Banner 引導用紅利玩最適合的遊戲。
  • ✓頂部 Toast：「Approved in · +৳1,200 has been approved. Bonus unlocked.」
  • ✓底部 Banner：「紅利可用 · Teen Patti [用紅利玩]」— 直接告知紅利使用場景
  • →Banner 的 CTA 文字「用紅利玩」比「繼續玩」更有誘因，因為玩家感受到額外價值
狀態 4 — 升 VIP 成功（Direction A）
通知宣布升等 + 確認到帳，底部 Banner（金色）引導進入 VIP 專屬桌，強調稀缺感。
  • ✓頂部 Toast（金色）：「Approved in · Gold VIP · +৳1,300 has been approved.」
  • ✓底部 Banner（金色）：「Gold VIP 專屬 · Live Baccarat [進入]」
  • →升等是情緒最高點，Banner 延續儀式感，讓玩家感受到 VIP 特權

原型 4 · Crypto 截圖啟發 · 轉換挽救設計
三個「最容易流失」時刻的解法

參考 MEXC、Bitget、Crypto.com 的存款流程截圖，提出三個對我們平台最有參考價值的設計改善：離開意圖問卷、失敗後清楚引導、支付方式信任訊號。

狀態 1 — 離開意圖問卷（Exit Intent Survey）
玩家進到 Step 3 表單頁後準備返回時，彈出底部問卷詢問原因。參考：Bitget（IMG_0720）
為什麼要做這個
  • !我們的數據：Step 3 表單頁有 17.49%（14,506 人）進來後只瀏覽、什麼都不做就離開
  • !現在我們只知道「有人離開」，但完全不知道為什麼 — 無法針對性改善
  • ✓這個問卷讓我們直接收集離開原因，同時也是一個挽留機制
設計重點
  • ✓偵測玩家點「返回」或滑動關閉時觸發（不主動打擾正在操作的用戶）
  • ✓選項：金額超出預算 / 不確定怎麼操作 / 想稍後再存 / 擔心安全問題 / 其他
  • ✓送出後 2 秒自動關閉，不強迫留下 — 降低玩家反感
  • →Bitget 實際截圖顯示：他們把「頁面看起來不可靠」和「不確定地址/費用」也列入選項 — 是誠實面對玩家疑慮的設計
雙重效益：問卷本身就是 UX 研究工具，累積回答後可以看出最常見的離開原因，每一個選項都對應一個可以改善的設計問題。
狀態 2 — 存款失敗後的清楚引導
失敗訊息不只說「失敗」，給出可能原因和明確的下一步。參考：Bitget 錯誤狀態 + 研究數據
為什麼要做這個
  • !研究數據：存款失敗後有 40% 的玩家直接放棄不再嘗試
  • !孟加拉市場特殊性：玩家不知道失敗是「技術問題」還是「交易被攔截」，這種模糊感比確定失敗更讓人焦慮
  • !現況：可能只顯示一個通用的「存款失敗」訊息，沒有下一步指引
設計重點
  • ✓區分三種失敗類型：技術失敗 / 輸入錯誤 / 交易被攔截（孟加拉特有）
  • ✓每種失敗對應不同的行動建議：重試 / 換方式 / 換金額 / 聯絡客服
  • ✓「換一個支付方式」按鈕直接出現，不讓玩家自己回去找
  • →Bitget：金額不符規則時立即紅色提示 + 「更正金額」按鈕 — 失敗訊息直接告訴你怎麼修
目標：把 40% 放棄不再嘗試，降低到 20% 以下。大部分失敗是可以自助解決的，只要給玩家正確的下一步。

原型 5 · 情境感知 Checkout
不同入口，看到不同的存款頁

從遊戲中途跳來存款的玩家，和從首頁主動進來的玩家，需要的東西完全不同。同一套存款頁對所有人，等於對誰都不夠好。參考 Uber Checkout Actions 和研究情境 04。

狀態 1 — 遊戲中途存款（極簡版）
玩家從 Slot / Casino 頁面點存款進來。情緒急迫，只想最快存完回去玩。不需要被說服，不需要看優惠。
設計邏輯
  • ✓隱藏優惠橫幅、隱藏方式說明文字 — 玩家已有上次設定，直接帶入
  • ✓頁面只有：金額輸入 + 快速金額選項 + 一個按鈕
  • ✓右上角顯示「X 返回遊戲」— 隨時可以關掉，降低心理壓力
  • ✓整個流程目標：10 秒內完成存款
數據依據
  • →我們的數據：Slot 頁面貢獻 15.1% 的存款入口，是第二大來源
  • →研究情境 04：遊戲中途被「打斷」的玩家，摩擦每多一步都是流失風險
這不是縮減功能，而是依據情境給對的功能。正常入口還是完整版，遊戲中途是極簡版。
狀態 2 — 推播深連結直達預填表單
玩家點推播通知裡的「存款」按鈕，直接進入已帶好上次設定的表單，不需要從頭走流程。
設計邏輯
  • ✓推播帶入 payload：上次方式（bKash）、上次金額（৳1,000）
  • ✓進入存款頁時顯示「通知帶入：上次設定」的提示條，告知玩家為什麼已經預填好
  • ✓玩家只需要確認金額 → 按一個按鈕 → 完成
技術需求
  • →推播通知的 deep link 帶入 method 和 last_amount 參數
  • →前端讀取 URL 參數，預填表單
目前的推播通知大概只是打開 app 首頁，玩家還需要自己走完整個流程。這個設計把「點通知到完成存款」縮短為 2 步。

原型 6 · 被動存款觸發
在對的時機，讓玩家想到存款

被動存款的關鍵是「時機」。三種觸發設計：新玩家首頁引導倒數、老玩家一鍵重複、遊戲中低餘額即時提示。對應研究中情境 A、B、04。

狀態 1 — 首頁 FTD Banner + 優惠倒數
新玩家完成註冊但還沒存款，首頁顯示步驟進度和優惠倒數，讓他知道「下一步是什麼」和「優惠快過期了」。
設計邏輯
  • ✓步驟進度條：「1.註冊 ✓ → 2.存款 → 3.開始玩」讓新玩家知道下一步是什麼
  • ✓優惠倒數計時：「首存優惠剩 11:23 過期」製造緊迫感（情境 B）
  • ✓顯示優惠內容：「存 ৳500 → 得 ৳1,000」讓玩家知道值得做
參考來源
  • →MEXC（截圖 IMG_0707/0708）：首頁顯示「1.Sign Up ✓ → 2.KYC → 3.Deposit → 4.Trade」的步驟進度
  • →研究數據：FTD 後 7 天是留存關鍵期，但目前新玩家進首頁不知道下一步做什麼
只對「尚未首存」的玩家顯示，首存完成後自動消失，不影響老玩家體驗。
狀態 2 — 一鍵重複存款
老玩家進到存款頁，直接顯示「上次存款紀錄」，一個按鈕就能重複，不需要重新選設定。
設計邏輯
  • ✓顯示上次存款的方式、金額、時間，讓玩家確認後一鍵送出
  • ✓保留「更換方式」和「調整金額」的出口，但不是預設路徑
  • !冷靜保護：30 分鐘內第二次觸發時，加入「確認再存」步驟，避免追損玩家無意識連續存款
研究指出：從「開始存款到完成」每少一個步驟，轉換率就提升。老玩家最理想的流程是：進入 → 看到上次設定 → 按確認 → 完成。
狀態 3 — 遊戲中低餘額提示
玩家在遊戲中餘額即將見底，直接在遊戲畫面出現存款提示，不需要離開遊戲才看到。
設計邏輯
  • ✓底部出現一個薄條：「餘額剩 ৳50 · 快速存 ৳500」
  • ✓點擊後進入情境感知極簡存款頁（原型 5 狀態 1）
  • ✓可以滑掉關閉，不強迫打擾
觸發條件（需後端配合）
  • →當餘額低於玩家「平均單次投注額 × 5」時觸發
  • →同一遊戲場次只觸發一次，避免重複打擾
對應研究情境 04（遊戲中餘額不足）。這批玩家是最急迫的存款者，在他們最需要的時刻出現，不需要說服。

狀態 1 — 存款等待頁動畫
存款送出後，不只是一個轉圈。用步驟動畫讓玩家知道「錢在哪裡」，消除不確定感。
為什麼現在的轉圈不夠
  • !轉圈沒有進度感 — 玩家不知道等了多久是正常、多久是卡住了
  • !孟加拉網路不穩定，玩家在轉圈時最容易誤以為失敗而重新送出，造成重複存款
改善設計
  • ✓三步驟動畫：「傳送中 ✓ → bKash 確認中（閃爍）→ 到帳（等待）」
  • ✓顯示預計到帳時間：「bKash 通常即時，預計 15 秒內完成」
  • ✓超過預計時間後，自動出現「還在處理中，請耐心等候」— 不讓玩家不知所措
這是成本最低的改善之一：只需要前端動畫，不需要後端 API 改動，卻能大幅降低等待焦慮。
狀態 2 — 弱網路等待狀態
存款送出後網路中斷，不立即顯示失敗，而是進入「等待重連」模式。孟加拉市場特有問題。
為什麼重要
  • !孟加拉農村地區網路不穩定，存款送出後中斷線的情況很常見
  • !玩家不知道「是交易失敗了，還是網路斷了」— 這個模糊感比確定失敗更糟
  • !很多玩家在這個時候重新送出，導致重複存款或重複扣款爭議
改善設計
  • ✓偵測到網路中斷後：顯示「網路中斷，正在等待重連」而非失敗
  • ✓明確說明：「您的存款申請已送出，請勿重新提交」
  • ✓重連後自動確認交易狀態，顯示正確結果
技術上只需要前端監聽 navigator.onLine 事件，成本很低。但對孟加拉市場的玩家信任感影響很大。
狀態 3 — 優惠視覺化計算機
存款金額輸入時，即時顯示「你實際可以玩多少錢」。把優惠從文字條款變成可感受的數字。
設計邏輯
  • ✓玩家輸入金額 → 下方即時顯示「您支付 ৳500 → 您可玩 ৳1,000（100% 加碼）」
  • ✓讓優惠的「錨定效應」發揮作用 — 研究顯示玩家存款金額常常剛好卡在優惠門檻
  • ✓如果輸入金額接近門檻（例如輸入 ৳480，門檻是 ৳500），顯示：「再存 ৳20 就能拿到 ৳500 加碼！」
技術需求
  • →前端讀取當前可用優惠的門檻和倍率規則
  • →即時計算：無需後端，純前端 JavaScript 計算
研究數據：玩家存款金額通常「剛好卡在優惠門檻」（行為錨定效應）。視覺化計算機讓這個效應更強，存款金額可能提升。
狀態 3 — 等待頁改版
對照 Figma 現有設計，三個關鍵改動讓玩家敢離開這個畫面
現有設計的問題
  • !唯一按鈕是「Close」— 關掉後去哪？玩家不知道
  • !沒有告訴玩家「到帳後會收到通知」— 玩家不敢離開，一直留在等待頁
  • !資訊只有「IN · Local bank · 金額」— 缺乏流程感，不知道現在在哪個步驟
改版的三個改動
  • ✓推播承諾 — 明確告知「到帳後你會立即收到通知」，讓玩家敢離開
  • ✓按鈕改成「去首頁」 — 給玩家明確的下一步，不是模糊的「Close」
  • ✓狀態里程碑 — 已送出 ✓ / 等待確認中 / 入帳完成，讓玩家看到自己在哪裡
不做的事
  • !不顯示「預計到帳時間」— 第三方確認時間無法預測，給了時間反而製造預期落差
這三個改動純前端實作，不需要後端 API 改動。最大的影響是：玩家離開等待頁去玩遊戲，等待期間情緒更穩定，到帳推播的點擊率也會更高。

原型 8 · 存款完成後的體驗
存款成功那一刻，和跨 app 引導

存款完成的那一刻是情緒最高點，也是建立信任感的黃金時機。慶祝動畫讓玩家感受到「完成感」；bKash 流程引導則解決很多玩家在跳出 app 時迷路的問題。

狀態 1 — 存款成功慶祝動畫
存款完成的瞬間加入彩帶動畫和數字滾動效果，讓玩家感受到「做到了」的完成感。
為什麼要做這個
  • ✓心理學研究：「完成感」（completion effect）能提升下一次回來再存款的意願
  • ✓存款成功是整個流程的情緒最高點，是建立正向體驗的最佳時機
  • ✓MEXC 抽獎動畫（截圖 IMG_0709）就是利用這個效果，讓存款完成「感覺像贏了什麼」
設計重點
  • ✓大顯示金額 + 綠色光環動畫 + 餘額數字滾動到新值
  • ✓成功後立即推薦「上次玩的遊戲」，讓玩家直接回去玩，不需要自己找
  • ✓動畫只播一次，2 秒後自動進入正常狀態，不影響操作
目前存款成功頁面可能只是一行「存款成功」的文字，這是最容易被忽略但效果顯著的改善點之一。
狀態 2 — bKash 跨 app 流程引導
玩家送出存款申請後，需要跳去 bKash app 輸入 PIN 確認。這個步驟很多玩家迷路或放棄。
現況問題
  • !玩家點「確認存款」後，系統跳到 bKash app，但玩家不清楚自己要在 bKash 裡做什麼
  • !很多人以為跳過去就完成了，沒有輸入 PIN → 回來發現存款未完成 → 以為失敗
  • !也有人在 bKash 裡點錯功能，導致交易失敗
改善設計
  • ✓跳出 bKash 之前，顯示三步驟圖解：「打開 bKash → 輸入 4 位 PIN → 按確認」
  • ✓每一步有視覺指示（步驟圓點 + 說明文字），讓玩家知道要做什麼
  • ✓「確認後自動回到平台」的說明，讓玩家知道不需要手動切換回來
這是純 UX 文字和視覺改善，零後端成本，但針對大量因為「不知道在 bKash 裡要做什麼」而放棄的玩家，效果直接。

原型 9 · 個人化存款引導
用過去行為，幫玩家做決定

玩家每次存款都要重新想「要存多少？用什麼方式？」——這是不必要的摩擦。根據歷史行為預填建議，加上 VIP 升級的目標感，讓存款決策變得更快、更有動機。

狀態 1 — 金額智能推薦
根據玩家歷史存款習慣，頁面一開就預選最常用金額，省去思考與輸入
設計說明
  • ✓顯示「您最常存」標籤，預選歷史最高頻金額（此例 ৳500）
  • ✓「上次存款」快捷鈕放在最前，一鍵重複上次行為
  • ✓AI 推薦晶片標記最常用選項，讓玩家感覺「被了解」
  • !需要最少 3 次存款紀錄才能啟用個人化推薦，首次存款顯示平台熱門金額
預期影響
  • ↑減少金額選擇時間，降低決策疲勞
  • ↑提高「一次點擊就完成選擇」的比例
💡 數據顯示 75% 玩家的存款金額都集中在固定 2–3 個數字，個人化推薦直接消除這個思考步驟。
狀態 2 — VIP 進度存款激勵
在存款頁顯示玩家距離下一 VIP 等級還差多少，讓金額選擇產生具體目標感
設計說明
  • ✓VIP 進度條顯示在金額選擇區上方，視覺上給出「這次存多少有意義」的錨點
  • ✓自動高亮「剛好升級」的最小金額按鈕（此例 ৳300），降低門檻
  • ✓升級後的好處簡短列出（更高返水、提款優先），讓玩家覺得值得
  • !只對距離升級 ≤ 20% 的玩家顯示，太遠的目標反而沒有激勵效果
預期影響
  • ↑提高平均存款金額（因為「湊整數升級」心理）
  • ↑增加 VIP 等級參與感，提升留存率

支付方式選擇是 Step 2 最大流失點（73% 離開）。智能排序讓玩家第一眼就看到「現在最快」的選項；若存款後超時未到帳，自助排查流程讓玩家不需等客服也能解決問題。

狀態 1 — 支付方式智能排序
根據當前時段的真實成功率與速度，動態排序支付方式，最穩最快的排在最前
設計說明
  • ✓每個方式顯示「現在到帳速度」和「成功率」，數字真實可信
  • ✓第一個選項自動加上「現在推薦」標籤，降低選擇困難
  • ✓正在維護或速度慢的方式顯示警告標籤，防止玩家選到出問題的渠道
  • !小字說明「根據過去 1 小時交易資料」，透明化排序依據，增加信任感
預期影響
  • ↑引導玩家選成功率高的渠道，降低整體失敗率
  • ↑玩家看到速度預告，等待期間焦慮感降低
  • ↑減少因選到壞渠道而產生的客服工單
💡 數據顯示 Step 2 是最大流失點。目前各方式沒有明確的速度/可靠度資訊，玩家憑感覺選，選錯了就流失。
狀態 2 — 存款未到帳自助排查
超過預期到帳時間後主動提示，引導玩家自行排查，減少客服壓力
設計說明
  • ✓超時後才觸發（不提前嚇玩家），橘色警示條簡單說明狀況
  • ✓三步驟 checklist：確認截圖 → 確認簡訊 → 聯繫客服，讓玩家有事可做
  • ✓每個 checklist 項目勾選後視覺反饋（綠勾），建立「進展感」
  • !最後一步才出現客服按鈕，確保玩家先自助排查，減少重複詢問
預期影響
  • ↓客服工單量降低（玩家自行確認截圖後許多問題消失）
  • ↑玩家感覺平台透明負責，信任感提升
💡 研究顯示存款失敗後若沒有明確引導，玩家會直接流失。有清晰的下一步，留存率明顯提高。

智慧推播通知
在對的時機，推對的內容給對的人

結合千人千面分群（L / B 層標籤）與行為事件觸發，三個最高 ROI 的推播情境：存款後優惠提醒、存款失敗挽回、生命週期個人化召回。開發成本低，可直接落地。

情境 1 — 存款到帳推播
觸發點：第三方回傳 deposit_success → 玩家已回首頁 → 推播通知到帳金額 + 優惠
為什麼這個時機最有效
  • ✓Lion 指出：存款後最多人查看 Promotion → 這是推播黃金窗口
  • ✓玩家剛完成存款，心理上處於「最願意消費」的狀態
  • →不立即推（避免與存款成功通知疊在一起），等 3 分鐘後玩家進入遊戲時推
對應分群標籤
  • LL04 新付費新戶 → 推首存專屬獎勵
  • LL05 活躍玩家 → 推一般優惠或 VIP 加碼
  • BSLOT 偏好 → 推 SLOT 專屬優惠；CASINO 偏好 → 推真人返水
開發成本評估
  • ✓監聽 deposit_success 事件 → 設 3min delay → 推播 API
  • ✓一個 event listener + 一組 push template，可與情境 2 共用架構
  • →預估開發：後端 1 天 + 文案 0.5 天
業界數據：存款後即時推播的點擊率比隨機推播高 3–4 倍。DraftKings 使用相同策略，存款後推播 CTR 達 22%。
情境 2 — 存款失敗挽回
觸發點：第三方回傳 deposit_failed → 玩家已離開存款頁 → 推播通知引導重試
為什麼這個最值得優先做
  • ✓玩家已有存款意願，只是遇到技術問題（網路斷線 / 銀行拒絕）
  • ✓這是「主動想存款卻沒成功」的族群，回應率極高
  • →5 分鐘後推（讓玩家有時間自行解決），點擊後 deep link 直接到一鍵重試頁，帶預填資料
  • !每次失敗只推一次，不重複騷擾
對應分群標籤
  • L所有 L 層：任何嘗試存款但失敗的玩家都觸發
  • →優先程度：L03 試玩新戶失敗 → 首存挽回 ROI 最高
開發成本評估
  • ✓架構與情境 1 完全相同，只是換觸發事件（deposit_failed）
  • ✓兩個情境可以同一批開發，邊際成本極低
  • →預估開發：後端 0.5 天（共用情境 1 架構）
這是 10 個 idea 中 ROI 最高的：流失的存款最貴，挽回成本卻最低。玩家主動想存款，推播只是在提醒他「路還在」。
情境 3 — 千人千面生命週期召回
觸發點：每日跑分群 → 依 L 層標籤推不同內容，在 B 層時段對齊發送
千人千面 × 推播的核心邏輯
  • LL06 待召回（14–30 天未下注）→ 推「限時回歸優惠」，製造緊迫感
  • LL08 流失玩家（30 天以上）→ 推「專屬回歸禮包」，獎勵要夠大才有效
  • LL03 試玩新戶（有下注但未入金）→ 推「首存加碼」，降低付費門檻
  • B時段對齊：讀 B 層「活躍時段標籤」→ 白天型在 14:00 推，晚間型在 21:00 推
為什麼不需要 ML
  • ✓B 層「活躍時段占比標籤」已算好每個玩家的最佳時段
  • ✓直接讀標籤 → 對應時段推播，效果等同於時段學習 ML，但不需要訓練模型
  • →預估開發：後端 2 天（排程 + 分群讀取）+ 文案 1 天
業界數據：分群推播 CTR 達 9.35%，是非分群推播的 14 倍。個人化推播比通用推播點擊率高 259%。
情境 4 — 到帳落地頁
玩家點擊推播通知後進入的頁面：存款確認 + 個人化推薦，把「到帳通知」從單純告知變成轉換入口
為什麼這個時機推薦最有效
  • ✓玩家剛確認存款成功 — 帳戶有錢，情緒最好，意願最高
  • ✓玩家主動點擊推播進來 — 不是被動打斷，是主動行為，轉換率遠高於一般頁面
  • !等待頁不適合推薦（存款未確認，用戶有懸念）；落地頁才是對的時機
千人千面推薦策略
  • LL03 試玩新戶 → 優惠倒數（加碼快到期）+ 新手入門遊戲
  • LL05 活躍玩家 → 繼續上次遊戲 + VIP 進度提示
  • LL06 待召回 → 回歸優惠剩餘時間 + 個人偏好遊戲
  • LL08 流失玩家 → 禮包已啟用確認 + 新遊戲探索
開發成本
  • ✓推播 deep link 帶入 player_id → 前端讀取分群標籤 → 對應顯示推薦內容
  • →預估：前端 1.5 天（頁面 + 分群邏輯）+ 推播 deep link 設定 0.5 天
點擊推播進入的用戶，已經完成「注意 → 點擊」兩步，只差最後一步「開始玩」。這個頁面的唯一目標就是讓這一步零阻力。
