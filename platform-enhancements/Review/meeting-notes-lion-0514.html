01 Landing Page 個人化標簽分類
IDEA 1 方向有疑慮 依賴廣告流量
提案概念
  • →依遊戲類型（Sports / Slot / Casino）分類廣告，玩家點哪類廣告 → 進入對應 Landing Page → 導入個人化首頁
  • →Landing Page 採靜態 HTML 機制（每 10 分鐘同步線上版），可放客戶空間或 AWS S3
  • →玩家可直接在 Landing Page 完成註冊，進站後只顯示對應類型遊戲（千人千面）
Lion 回饋
  • !Sports / Casino 大分類已不夠用，許多玩家兩樣都玩 → 需參考 CRM 現有細分標簽系統
  • ?Guest（未登入）用戶的標簽怎麼設定？需有預設邏輯
  • !整個架構依賴廣告流量，但廣告團隊轉換率差、常被封 → 做好了也可能沒效果
  • ?標簽來源與準確度如何驗證？具體怎麼落地？
02 Landing Page 極簡化首頁
IDEA 2 待釐清 需要 Wireframe
提案概念
  • →不載入整個主站，改成極簡：Logo + 搜尋列 + 遊戲類型 Banner
  • →未登入：秀遊戲類型區塊，從點擊行為判斷喜好；已登入：直接秀「我的最愛」遊戲
  • →全站搜尋涵蓋遊戲 + Promotion；點 JILI → 進 JILI 大廳後可在大廳內切換遊戲
Lion 回饋
  • ?JILI Lobby 能否切換其他廠商遊戲？需先確認（Backend / AWC 錢包串接問題）
  • ?全站搜尋要做到什麼程度？跨 Casino / Slot 的 API 怎麼設定？
  • ↗需要 Wireframe，否則概念太抽象難以評估
  • ↗向 Tonya 取得 V2 / V3 首頁點擊率 Top 3，找出哪些可留、哪些可拿掉
03 Welcome Offer / CRM 個人化
方向有疑慮 依賴廣告團隊
提案概念
新玩家從不同渠道（Sports / Slot）進入 → 根據來源客製化 Welcome Offer → 提升註冊轉換率
Lion 回饋
  • !廣告團隊問題嚴重：轉換率差、Facebook/TikTok 廣告一直被封、CAPI 也沒用好；SEO 相對較好
  • !這個方向太偏 CRM / 廣告渠道，成效完全取決於廣告團隊表現 → 我們做好了也可能看不出效果
★ 核心提醒：做的東西要不依賴別人，我們自己能控制的才有意義
04 存款個人設定
方向認可 ✓ 不依賴外部 Payment
提案概念
記錄玩家上次存款設定（金額 + 支付方式），下次存款時自動帶入；用 JSON 檔儲存個人設定（機制已有，待確認儲存位置）
Lion 回饋
  • ✓方向正確：不依賴任何外部資源，自己就能做到
  • ?永久記憶 vs 非永久記憶的定義是什麼？
  • ?帶入設定後，若玩家想改金額（上次存 1000，這次只存 10），UX 如何讓他方便修改？避免「記憶反而造成困擾」
  • ↗可擴展：不只金額，連支付方式、上次完整設定都帶入
05 TS 活化 / 問卷回饋
需重新設計 套利風險
提案概念
鼓勵玩家填問卷，送小額獎勵（Free Spin / Bonus）；玩家提交 Bug 回饋 → 給予獎勵
Lion 回饋
主要風險
  • !BOT 可大量註冊 → 大量填問卷 → 領獎金出金（套利）
  • !玩家可能隨意亂填，問卷有效性存疑
  • !客戶 TS 管理困難，很難教育標準化流程
可行替代方向
  • ✓讓玩家用簡單行為回報問題（遇 Bug 時一鍵回報）→ 目的明確、較難套利
  • ↗技術 TS ≠ 客戶 TS（面對玩家的客服）
06 低 Balance 提醒 / 破產錢包
可做，需想清楚 套利風險
提案概念
玩家餘額快用完時彈出提醒或 Promotion，刺激繼續存款（對應 CRM 的「破產獎金」概念）
Lion 回饋
  • ?給的條件是什麼？（大戶？連存三次？讓利？）
  • !給完獎勵後，玩家的「下一步」是否會再存款？若拿完打完就走 → 對營運方沒有意義
  • !需防套利：機制要讓玩家感覺「平台在幫我」而非隨意補貼
★ 核心目標：給完之後玩家要有動力再存款，才對營運方有價值
07 智慧推播通知
可做，需數據支撐
提案概念
推播不只用在存款成功，也推送 Promotion、新遊戲、VIP 升等提醒、新任務
Lion 回饋
  • ★數據是關鍵：要用數據找出最佳推播時機，而不是亂推
  • ↗分析玩家點擊 Promotion 的前一步行為 → 例如：存款後最多人看 Promotion → 存款成功後推播最有效
  • ↗建立迴推機制：若多次推播都沒被點 → 自動判定時機不對 → 調整策略
  • !推播若設在首頁登入時觸發 → 會加重首頁 loading 負擔
08 網頁圖片載入優化
待落地方案 孟加拉市場
提案概念
網路不佳時先載低解析圖，網速夠再換高清（孟加拉市場為主要痛點）；PNG 全面改為 WebP / JPG
Lion 回饋
  • !Cloudflare CDN 本身有自適應圖片功能，但我們沒有開啟
  • !目前 Lazy Loading 用原始高解析圖，沒依網速調整；1x / 2x / 3x 多版本當初沒落地
  • ↗用孟加拉 VPN 實際測試 UAT，親身體驗低網速下的真實表現
  • ↗先測出數據：1x vs 3x 圖的載入差異有多大？有數據才能說服後端
  • ?WebP 部分舊手機不支援時要怎麼 fallback？兩套圖同時存在，總大小會不會比 PNG 更大？
  • ?PNG 當初選因 Brian 要求顏色不被壓縮 → 改格式需提出完整落地方案說服後端
