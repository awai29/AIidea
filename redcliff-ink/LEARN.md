# LEARN.md — 水墨赤壁是怎麼做出來的

用淺顯的語言記錄這個專案的架構、技術決策，以及踩過的坑。

---

## 這個網站是什麼

一個純前端的 3D 互動畫卷：用「水墨畫」的視覺風格，分五個章節講述三國赤壁之戰。
不需要後端、不需要資料庫，所有檔案就是幾個 HTML / CSS / JS 純文字檔。

**怎麼打開**：因為瀏覽器安全限制，不能直接雙擊 index.html，要先啟動一個小伺服器：

```bash
cd aiproject/redcliff-ink
python3 -m http.server 8765
# 然後用瀏覽器打開 http://localhost:8765
```

## 技術架構（各部分如何連接）

```
index.html        ← 網頁骨架：3D 畫布 + 文字面板等 UI
css/style.css     ← 外觀：宣紙底色、直書標題、章節卡片
js/story.js       ← 「劇本」：五章的標題、內文、鏡頭位置
js/shaders.js     ← 「畫筆」：跑在顯示卡上的小程式（GLSL）
js/main.js        ← 「導演」：組裝場景、處理滑鼠互動、運鏡
tests/visual-check.mjs ← 自動化測試：開瀏覽器逐章截圖
```

### 名詞解釋

- **three.js**：JavaScript 的 3D 引擎。我們用它擺放江面、山、戰船，像在搭一個小模型劇場。
- **Shader（著色器）**：直接在顯示卡上執行的小程式，負責計算「每一個像素該是什麼顏色」。
  水墨暈染、漣漪、火光這些效果，都是 shader 一個像素一個像素算出來的。
- **fbm 雜訊**：把好幾層隨機紋理疊在一起，就會得到像雲、像墨暈的自然紋理。
  整個網站的「墨味」幾乎都來自這一招。

### 互動是怎麼運作的

1. **滑鼠掃過江面出現墨痕**：用「射線偵測」（raycast，想像從滑鼠位置往畫面裡射一條看不見的線）
   找到滑鼠指到江面的哪個點，把座標傳給水面 shader，shader 在那個點畫出一圈圈擴散、
   邊緣毛毛的墨環。
2. **hover 戰船**：射線指到船 → 船的 shader 收到 `uHover` 數值 → 船身泛起朱砂色，
   旁邊跟著顯示船名標籤。
3. **點擊戰船**：平常顯示史料小卡；在第四章點曹軍船會「縱火」——
   船的 shader 用雜訊決定焦黑蔓延的形狀，再掛上一團火焰粒子，
   並且每隔 0.65 秒延燒到隔壁的船（呼應「鐵索連舟」）。
4. **章節切換**：每章在 story.js 裡寫好攝影機位置，切章時用自己寫的補間動畫
   （easeInOutCubic：先慢、中快、後慢）平滑運鏡過去。

## 技術決策的原因

| 決策 | 原因 |
|------|------|
| 純 HTML/JS，不用 React/Next.js | 內容是單一畫卷頁，不需要框架；檔案越少越好懂 |
| three.js 從 CDN 載入（importmap） | 不用 npm install、不用打包工具，開伺服器就能跑 |
| 自己寫補間動畫，不裝 GSAP | 只需要一個鏡頭移動效果，30 行內搞定，少一個依賴 |
| 視覺效果全用 shader，不用貼圖圖片 | 沒有圖片授權問題、檔案極小、而且墨暈可以「活的」隨時間流動 |
| 字體用 Cactus Classical Serif | Google Fonts 上少數支援繁體中文的古典明體，符合水墨氛圍 |

## 遇到的錯誤與修復

### 1. headless 瀏覽器開不出 WebGL
- **現象**：Playwright 無頭模式報錯 `Could not create a WebGL context`。
- **原因**：無頭模式用軟體模擬顯卡（SwiftShader），在這台機器上會失敗。這不是程式碼 bug。
- **修復**：測試改用 `headless: false`（開真的瀏覽器視窗）就能正常渲染與截圖。
- **教訓**：**測 WebGL/3D 網站時，Playwright 要用有視窗模式**。

### 2. 戰船像「圓盤蛋糕」
- **原因一**：帆轉了 90 度變成側面對著鏡頭，薄得看不見。
- **原因二**：鏡頭太高太俯視，船身被壓扁成橢圓。
- **修復**：帆改成正對鏡頭的「上寬下窄」中式硬帆，並把每一章的鏡頭高度壓低、改成側望。
- **教訓**：3D 物件「做得對」不等於「看起來對」，**鏡頭角度跟模型本身一樣重要**。

### 3. 火光把整個畫面染橘，墨味盡失
- **原因**：江面火光的衰減半徑設太大、強度上限太高。
- **修復**：縮小衰減半徑（`exp(-d*0.055)` → `exp(-d*0.10)`）、強度上限壓到 0.5，
  並把整體火光目標值乘 0.8。
- **教訓**：特效要為整體風格服務——「夠看見」就好，不要「最大聲」。

### 4. 滑鼠漣漪看不見
- **過程**：先懷疑漣漪根本沒在渲染 → 寫了一個 debug 腳本直接塞入超強漣漪 → 確認渲染正常，
  問題只是滑鼠漣漪「強度太弱」。
- **教訓**：除錯時先把可疑功能「開到最大」確認它存在，再回頭調參數，
  不要一開始就亂改程式。

## 未來要避免的陷阱

- shader 的 `uniform` 陣列（如 16 個漣漪）有上限，超過就要淘汰最舊的，否則會出錯。
- `ExtrudeGeometry` 擠出方向是 z 軸，要 `rotateX(-90°)` 才會變成「高度」。
- 自動化測試後門 `window.__APP` 留在程式裡（不影響使用者），日後改版測試還用得到。
